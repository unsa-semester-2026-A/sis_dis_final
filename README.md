## Reglas del equipo

- Regla de Oro en GitHub Projects: Si una tarea no está en el tablero, no existe.
  Nadie debe trabajar en algo que no esté registrado y asignado.
  
- Límites de Trabajo en Progreso (WIP): Cada integrante solo puede tener una tarea
  en la columna "En Progreso" a la vez. Esto evita el trabajo a medias.
  
- Flujo de Ramas (Git Workflow): Nadie hace commits directos a la rama main o
  master. Todo desarrollo se hace en una rama separada y
  se integra mediante un Pull Request (PR).
  
- Revisiones de Código: Ningún PR se aprueba sin que al menos un integrante
  distinto al autor lo revise. Esto previene cuellos de botella y asegura que
  todos entiendan el sistema.
  
- Documentación Viva: Las decisiones de arquitectura y los contratos de las APIs
  se documentan en la GitHub Wiki antes de programar, no después. Se sigue el
  marco de `User Story Mapping` para la gestión de los requerimientos.

- Todo el código (incluida la documentación) debe estar en inglés.

- Antes de realizar una pull request, leer la [Guia de
contribución](./CONTRIBUTING.md)
